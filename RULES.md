# RULES.md — Техническая спецификация и правила калькулятора ADY

## 1. Архитектурные принципы
* **NLU & Парсинг (Gemini API):** Отвечает исключительно за извлечение ключевых сущностей (raw_from, raw_to) из свободной речи пользователя. Модель НЕ выполняет тарифных расчетов и не определяет ЕСР-коды самостоятельно.
* **Детерминированный движок (Python Backend):** Выполняет 100% бизнес-логики, включая определение типов перевозки (Транзит, Импорт, Экспорт, Внутренняя), поиск расстояний и итоговое форматирование.
* **Централизация синонимов (data/stations_mapping.py):** Единственный источник правды для всех алиасов, опечаток, исторических названий, кодов ЕСР и пограничных статусов. Вся сложная логика синонимов инкапсулирована внутри справочника, модуль core/router.py очищен от условных операторов if/elif для поиска имён.

## 3. Логика типов перевозок (ShipmentType)
Определение типа перевозки происходит автоматически на основе пограничных статусов (is_border) начальной и конечной станций:

1. **Транзит (Transit):** Откуда (is_border=True) -> Куда (is_border=True)
   Пример: Ялама -> Беюк Кясик, Курык -> Беюк Кясик, Астара -> ТРК.
2. **Импорт (Import):** Откуда (is_border=True) -> Куда (is_border=False)
   Пример: Ялама -> Абшерон, ТРК -> Баладжары.
3. **Экспорт (Export):** Откуда (is_border=False) -> Куда (is_border=True)
   Пример: Абшерон -> Ялама, Гянджа -> Беюк Кясик.
4. **Внутренняя (Local/Domestic):** Откуда (is_border=False) -> Куда (is_border=False)
   Пример: Хырдалан -> Гянджа, Абшерон -> Баладжары.

## 4. Особая бизнес-логика паромных переправ и узлов (Алят)
* **Привязка к ЕСР:** Паромные и морские направления привязаны к соответствующим экспортным терминалам Алята для точного поиска расстояний в матрице:
  * Курык / Курик / Актау -> ЕСР 553002 (Ələt eksport-Kurik)
  * ТРК / Туркменбаши / Туркмен -> ЕСР 548803 (Ələt eksport-Türk.)
  * Актау -> ЕСР 549204 (Ələt eksport-Aktau)
* **Правило форматирования вывода ("Алят-эксп."):**
  Если пользователь напрямую запрашивает сокращения вроде «Алят экс/експ», система корректно определяет узел, но при форматировании вывода в интерфейсе скрывает код ЕСР, отдавая чистый интерфейсный вид: Алят-эксп. (без скобок с кодом).

## 7. Логика расчета тарифов, Валютная система (USD / CHF) и Таблицы 3 и 4
1. **Валюта расчета:** Все итоговые тарифы провозной платы выводятся строго в **долларах США (USD)**.
2. **Валюта базовых ставок:** Все базовые таблицы (Таблица 3, Таблица 4) хранят тарифные ставки в **Швейцарских франках (CHF)** за 1 тонну.
3. **Конвертация валют:** Курс CHF -> USD подтягивается динамически из `data/currency_rates.py` по дате перевозки `shipment_date` (курс 0.79 для Q3 2026, 0.81 для Q4 2026).
   $$\text{Базовая ставка USD} = \frac{\text{Базовая ставка CHF}}{\text{Курс конвертации}}$$
4. **Выбор Базовой Таблицы:**
   * **Импорт / Экспорт:** Используют **Таблицу 3** (`data/Table_3_Tariffs.txt`, модуль `core/tables/table_3.py`) для универсальных вагонов.
   * **Транзит:** Использует **Таблицу 4** (`data/Table_4_Tariffs.txt`, модуль `core/tables/table_4.py`) для универсальных вагонов (крытый, полувагон, платформа).
   * **Специализированный подвижной состав (СПС):** Использует **Таблицу 5** (`data/Table_5_Tariffs.txt`, модуль `core/tables/table_5.py`) для рефрижераторных вагонов/секций, АРВ, ИВ-термосов,         ледников, автомобилевозов, двухъярусных платформ, ИНВ/АНВ и дизель-генераторов.
5. **Последовательность умножения коэффициентов:**
   * **Шаг 1:** Базовая ставка в USD ($\text{CHF} / \text{Курс}$).
   * **Шаг 2:** Специфические коэффициенты по грузу/маршруту (например, 1.04 для леса и черных металлов).
   * **Шаг 3:** Коэффициент международной груженой перевозки (1.015).
   * **Шаг 4:** Коэффициент приватного вагона СПС (0.85).

## 9. Архитектура и правила разделения ответственности (Separation of Concerns)

** **Локальные правила таблиц — строго внутри своих модулей:**
  Все специфичные коэффициенты и условия, относящиеся к конкретной тарифной сетке, должны вычисляться исключительно внутри своего модуля (`core/tables/table_X.py`). 
  *Пример (Таблица 5):* Модуль `core/tables/table_5.py` обслуживает **специализированный подвижной состав (СПС)**. Внутри него строго изолированно рассчитываются:
    * Логика выбора колонок по весу (<25т / >=25т) и состоянию (гружёный/порожний).
    * Коэффициенты составности рефсекции: 1 вагон (1.70), 2 вагона (1.40), 3 вагона (1.10), 4 вагона (1.00), 5+ вагонов (0.85).
    * Скидка 0.60 на плодоовощную продукцию стран СНГ/ТС (коды ГНГ 07, 08, 12129100).
    * Аксиальные ставки: 0.12 CHF/ось-км (для дизель-генераторов) и 0.10 CHF/ось-км (для порожнего вагона в составе гружёной секции).
    * Коэффициент 0.80 для двухъярусных платформ-автовозов..

## 10. Разделение ответственности и обработка расстояний (Router vs Calculator)

* **Чистое разделение ролей (Router / Calculator):**
  * **Роутер (`core/router.py`):** Занимается географической и нормативной обработкой маршрута. Рассчитывает фактическое расстояние из CSV (`distance_km`) и проверяет тарифные минимумы ADY ($101\text{ км}$ для экспорта, $151\text{ км}$ для импорта). При срабатывании правила формирует нормативное значение `calculated_distance_km`, а также записывает метаданные правила (`rule_code` и `params`: `actual` и `applied`).
  * **Калькулятор (`core/calculator.py`):** Выступает в роли «чистого Повара». Принимает отфильтрованный нормативный километраж (`route_res.calculated_distance_km`) через параметр `distance_km` и выполняет строго финансовые расчёты базовых ставок и коэффициентов.
* **Сохранение метаданных для отчётов:**
  * Фактическое расстояние из базы данных ($67\text{ км}$) не теряется и сохраняется в объекте `RouteResult`.
  * При передаче данных в интерфейсы (`app.py`, тесты, печать) уведомление о применённом минимальном расстоянии формируется на основе `route_res.rule_code` и `route_res.params`, обеспечивая прозрачность расчётов для пользователя на всех поддерживаемых языках (RU / AZ / EN).

* **Централизация сквозных правил (`core/main_rules.py`):**
  Правила Тарифного руководства, применяемые к нескольким таблицам одновременно (например, коэффициент 1.20 на цветные/драгоценные металлы по п. 3.1.1 для Таблиц 3 и 4, надбавка 1.50 на импорт/экспорт, индексация 1.015, скидка 0.85 на приватные вагоны), должны жить строго в `core/main_rules.py`. Дублировать сквозную логику в модулях таблиц запрещено.

* **Роль главного калькулятора (`core/calculator.py`):**
  Файл `core/calculator.py` выступает исключительно в роли чистого оркестратора. В нём запрещен хардкод коэффициентов и ручная проверка условий правил. Его задача — вызвать модуль соответствующей таблицы, запустить `apply_main_rules`, рассчитать итоговые суммы и собрать единый список уведомлений.

* **Прозрачность вычислений и структура ответа:**
  Каждый модуль расчета (`main_rules` и модули из `tables/`) должен возвращать не просто числовое значение ставки (`float`), а словарь с детальной структурой: итоговую/базовую ставку и список примененных правил `applied_rules` с указанием `rule_code` и `params`.

* **Строгая локализация без заглушек:**
  Все `rule_code` должны строго соответствовать ключам из `data/translations.py`. Запрещено внедрять ручной текстовый вывод или временные заглушки прямо в код расчетов или тестов.

  ## 11. 3.1.2.7. Перевозка на специализированных платформах (>19 м)
- **Условия применения**:
  - Тип вагона: специализированная платформа для крупнотоннажных контейнеров (`is_specialized_platform = True`).
  - Длина: расстояние между осями сцепа автосцепок более 19 метров (`coupling_distance_over_19m = True`).
  - Принадлежность: инвентарный парк / МПС (`is_private_wagon = False`).
  - Груз: габаритный / очерченный (`is_oversized_cargo = True`).
- **Расчёт тарифа**:
  - Базовая ставка определяется по **Таблице 3** (Импорт/Экспорт/Внутренняя) или **Таблице 4** (Транзит).
  - К итоговой ставке применяется повышающий коэффициент **1.20** (`MAIN_COEFF_SPECIAL_PLATFORM_OVER_19M_1_20`).

### 3.1.2.8. Перевозка в других видах специализированного подвижного состава
- **Условия применения**:
  - Грузы, перевозимые в специализированных вагонах, не подпадающие под пункты 3.1.2.1–3.1.2.7.
- **Расчёт тарифа**:
  - Провозная плата рассчитывается по базовым тарифным ставкам для универсальных вагонов (**Таблицы 3 и 4**) без дополнительных специальных надбавок.
 
 ## 11. ### 3.2.2. Перевозка собственных (приватных) и арендованных порожних вагонов

- **Коды ГНГ (YHN)**: `99210000`, `99213000`, `99220000`, `99223000`.
- **Условия применения**:
  - Вагон следует в порожнем состоянии (`is_empty_wagon = True`).
  - Принадлежность: собственный / приватный / арендованный (`is_private_wagon = True`).
  - Тип вагона: любой, кроме транспортеров (`wagon_type != 'transporter'`).
- **Расчёт тарифа**:
  - Базовая ставка рассчитывается напрямую по формуле:
    $$\text{Ставка (CHF)} = \text{Расстояние (км)} \times \text{Количество осей} \times 0.10\text{ CHF}$$
  - Если количество осей не указано пользователем, по умолчанию принимается `axle_count = 4`.
  - Код ГНГ по умолчанию при отсутствии явного указания: `99220000`.
  - Стандартные **Таблицы 3 и 4** в данном расчете не используются.
  - Понижающий коэффициент приватного вагона `0.85` и коэффициент `1.015` **не применяются**.
  - Применяется код уведомления `MAIN_EMPTY_PRIVATE_WAGON_0_10_AXLE_KM`.
 
 №№ 12. 3.2.6. Перевозка автопоездов, прицепов, полуприцепов и съемных автокузовов на спецплатформах

- **Типы подвижного состава**: `road_train`, `semi_trailer`, `road_train_platform`, `автопоезд`, `полуприцеп`.
- **Условия применения**:
  - Перевозка автопоездов, прицепов, полуприцепов и съемных автомобильных кузовов (кроме контейнеров) на собственных (приватных) или арендованных специализированных платформах.
  - Применяется как для груженого, так и для порожнего состояния.
- **Расчёт тарифа**:
  - Базовая ставка определяется strictly по **Таблице 5**:
    - **Гружёный состояние**: Используется **колонка 7** Таблицы 5 (за 1 тонну).
    - **Порожнее состояние**: Используется **колонка 8** Таблицы 5 (за вагон).
  - На порожнее состояние автотехники по п. 3.2.6 **не распространяется** расчет по Пункту 3.2.2 ($0.10\text{ CHF/ось-км}$).
  - Для собственных (приватных) платформ сработает понижающий коэффициент **0.85** (`MAIN_COEFF_0_85_PRIVATE_WAGON`).
  - Формируется код уведомления `ROAD_TRAIN_SPECIAL_PLATFORM_RULE_3_2_6`.
